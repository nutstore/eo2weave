# AGENTS.md

Instructions for AI coding agents working in this repository (Claude Code, Cursor, Codex, and EO2Weave's built-in agent, which discovers this file via its Project Instructions beacon).

## Project Overview

EO2Weave (CreatorWeave) is an AI-native creator workspace that enables natural-language interaction with local files. Everything runs client-side in the browser (React + TypeScript + Rust/WASM + Pyodide), with a browser extension and a native host for OS integration.

## Repository Layout

| Path | Contents |
|---|---|
| `web/` | Main application — **Next.js App Router** (`app/`), AI agent loop (`agent/`), React UI (`components/`), state (`store/`), OPFS (`opfs/`), SQLite (`sqlite/`), skills (`skills/`), MCP/WebMCP (`mcp/`, `webmcp/`), Pyodide (`python/`) |
| `web/wasm/` | Rust → WASM build artifacts consumed by the web app |
| `browser-extension/` | WXT Chrome MV3 extension (`entrypoints/`) |
| `browser-extension/native-host/` | Rust native messaging host; installers at `install.sh` / `install.ps1` / `installer/` |
| `packages/` | Shared workspace packages: `ui` (shadcn/Tailwind), `config`, `i18n`, `shared`, `conversation`, `skills-system` |
| `skill-store/` | Skill store catalog source |
| `docs/` | User & developer docs (source for the in-app docs center) |

> ⚠️ Some older docs (including previous revisions of `CLAUDE.md`) describe a pre-Next.js layout with `web/src/` and a top-level `wasm/` directory. That layout no longer exists — the table above is authoritative. Deeper guides: `DEVELOPER_GUIDE.md`, `DESIGN.md`.

## Commands

```bash
pnpm install                 # workspace install (pnpm only — no npm/yarn)
make dev                     # web dev server (port 5173)
make build                   # full build (extension assets + web)
make lint                    # ESLint (web)
make typecheck               # TypeScript check (web)
make test                    # web unit tests
cd web && pnpm test:run -- <path>        # single test file
cd browser-extension && pnpm build       # wxt build → chrome-mv3/
cd browser-extension && pnpm build:store # store build (CW_STORE_BUILD=1)
cd browser-extension/native-host && cargo build --release  # native host
```

### Test execution rules

- Focus implementation and tests on normal usage and explicitly requested behavior. Do not add special-case logic or tests for rare edge cases unless the requirements explicitly call for them; keep code simple and avoid unnecessary branches and defensive state.
- The **full** `pnpm test:run` suite can exceed command timeouts. Run by directory chunks instead:
  - `cd web && pnpm test:run agent`
  - `cd web && pnpm test:run components`
  - `cd web && pnpm test:run store sqlite services`
  - `cd web && pnpm test:run opfs`
  - `cd web && pnpm test:run hooks utils lib`
- After any source change, run the relevant chunk **plus** `pnpm typecheck` before claiming the task is done.

## Conventions (hard rules)

- **Commits**: English, [Conventional Commits](https://www.conventionalcommits.org/) — `feat(scope): …`, `fix: …`, etc. `CHANGELOG.md` is generated by `git-cliff` from commit messages; non-conventional commits are silently skipped, and **`CHANGELOG.md` must never be hand-edited**.
- **Versioning**: the extension version's single source of truth is `browser-extension/package.json`. Release cadence: Friday release train (fix → patch, features → minor); urgent midweek fixes bump immediately.
- **Code comments**: English. User-facing copy can be any language; i18n strings live in `packages/i18n` and all four locales (`en`/`zh`/`ja`/`ko`) must stay in sync.
- **TypeScript**: strict mode; use the `@/` path alias inside `web/`.
- **UI components**: shared components live in `packages/ui`. After modifying them, rebuild with `cd packages/ui && pnpm build` or `web/` will not pick up the change. Note: `BrandButton` has **no `default` variant** for normal buttons (use `primary`/`secondary`/`outline`/`ghost`/`danger`; `default` is icon-button-only).
- **Icons**: file icons use `@iconify/react` with the `vscode-icons` prefix; inline SVGs must have a valid `d` attribute.

## Known Pitfalls

- **wxt output directories**: `wxt build` → `chrome-mv3/`, `wxt build -m development` → `chrome-mv3-dev/`. The two are independent — rebuild whichever the user actually loads.
- **Storage layers**: SQLite WASM (worker + OPFS VFS) is the main database; OPFS caches file contents; IndexedDB is a legacy fallback only.
- **Extension version chain**: `browser-extension/package.json` version → `web/next.config.mjs` (`NEXT_PUBLIC_EXTENSION_LATEST_VERSION`) → settings page / outdated banner.
- **Markdown relative links** are intercepted by the app's own renderer — bare relative `href`s must be resolved against workspace files, never the site URL.
- **Tests and singletons**: many modules are module-level singletons (caches, managers). In tests, prefer factory-created instances and `vi.resetModules()` over shared state; `vi.clearAllMocks()` does not clear queued `mockResolvedValueOnce` responses.

## Verification Checklist (before finishing any task)

1. Relevant test chunk(s) pass.
2. `make typecheck` (or `cd web && pnpm typecheck`) passes.
3. If `packages/ui` changed: rebuilt and consuming code re-verified.
4. If commits were created: English Conventional Commits only.
